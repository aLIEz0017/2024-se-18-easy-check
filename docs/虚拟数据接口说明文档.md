# 虚拟数据接口说明文档

> 本文档记录前端临时功能测试用的虚拟数据接口。  
> 这些接口仅用于前端页面未完成真实联调前的占位测试，不属于正式业务接口；后续真实接口稳定后必须删除。

---

## 一、设计目标

- 为前端提供稳定的临时 JSON 数据，便于登录页、活动大厅、票夹、Dashboard、核销工作台等页面做功能测试。
- 不覆盖正式接口路径，避免影响真实业务联调。
- 不依赖数据库，不写入 `user/event/ticket` 等业务表。
- 所有返回结构仍遵守项目统一 `Result<T>` 响应格式。

---

## 二、Mock 方案说明

本项目提供两种 Mock 方案，可根据开发环境选择使用：

### 方案 A：后端 Mock 接口（需要后端运行环境）

所有虚拟接口统一挂在 `/api/v1/mock/**` 路径下，由后端 `MockDataController.java` 提供数据。

### 方案 B：前端本地 Mock 数据（无需后端环境，推荐纯前端开发时使用）

所有 API 文件（`api/*.js`）中的函数直接返回 `Promise.resolve()` 本地 Mock 数据，**不发起网络请求**。

**当前状态**：已切换为方案 B（前端本地 Mock），所有 API 文件均已修改为直接返回本地数据。

---

## 三、路径约定（方案 A：后端 Mock）

所有虚拟接口统一挂在：

```text
/api/v1/mock/**
```

示例：

```text
GET /api/v1/mock/event/list
GET /api/v1/mock/dashboard/overview
POST /api/v1/mock/ticket/checkin
```

前端如果要临时使用虚拟接口，可以在对应 API 调用路径前增加 `/mock`。例如：

```js
// 正式接口
request.get('/event/list', { params })

// 临时虚拟接口
request.get('/mock/event/list', { params })
```

## 五、前端使用方式

### 5.1 方案 A：临时切换 API 路径（需要后端）

前端现有 `request.js` 的 `baseURL` 是 `/api/v1`，因此调用 mock 接口时，只需要把模块路径前加上 `/mock`。

示例：

```js
// 正式活动列表接口
request.get('/event/list', { params })

// 临时活动列表 mock 接口
request.get('/mock/event/list', { params })
```

不建议直接修改 `request.js` 的 `baseURL`，否则所有正式接口都会被整体切换，容易影响其他成员联调。推荐在具体 API 文件里临时替换路径，测试完成后按本文档第八章删除。

### 5.2 方案 B：前端本地 Mock（当前使用，无需后端）

所有 API 文件已修改为直接返回本地 Mock 数据，**不发起网络请求**。

以 `frontend/src/api/dashboard.js` 为例：

```js
// 当前写法（直接返回本地 Mock 数据）
export function getDashboardOverviewAPI() {
  return Promise.resolve(MOCK_OVERVIEW)
}

// 正式联调时切换回：
// export function getDashboardOverviewAPI() {
//   return request.get('/dashboard/overview')
// }
```

同理，所有 API 文件均采用相同的模式：

| 前端 API 文件 | 当前模式 | 正式联调时切换为 |
|------|------|------|
| `api/auth.js` | `Promise.resolve(本地数据)` | `request.post('/auth/login')` |
| `api/auth.js` | `Promise.resolve(本地数据)` | `request.post('/auth/register')` |
| `api/user.js` | `Promise.resolve(本地数据)` | `request.put('/user/profile')` |
| `api/event.js` | `Promise.resolve(本地数据)` | `request.get('/event/list')` |
| `api/event.js` | `Promise.resolve(本地数据)` | `request.get('/event/{id}')` |
| `api/dashboard.js` | `Promise.resolve(本地数据)` | `request.get('/dashboard/overview')` |
| `api/dashboard.js` | `Promise.resolve(本地数据)` | `request.get('/dashboard/event/{id}')` |
| `api/dashboard.js` | `Promise.resolve(本地数据)` | `request.get('/dashboard/prediction/{id}')` |

## 六、前端使用方式（方案 A：后端 Mock）

### 6.1 登录测试

临时把 `frontend/src/api/auth.js` 的登录接口改为：

```js
export function loginAPI(data) {
  return request.post('/mock/auth/login', data)
}
```

前端登录页输入任意账号和密码即可。mock 接口默认返回普通参会者：

```json
{
  "username": "attendee_demo",
  "password": "123456"
}
```

如果要测试举办方登录，可让前端请求体带上：

```json
{
  "username": "organizer_demo",
  "password": "123456",
  "role": "organizer"
}
```

返回示例：

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "mock-token-organizer",
    "userId": 2,
    "username": "organizer_demo",
    "role": "organizer"
  }
}
```

前端可用这个返回值测试 `authStore.login()`、localStorage 写入、路由跳转和角色守卫。

### 6.2 注册测试

临时把 `frontend/src/api/auth.js` 的注册接口改为：

```js
export function registerAPI(data) {
  return request.post('/mock/auth/register', data)
}
```

普通参会者注册请求：

```json
{
  "username": "new_attendee",
  "password": "123456",
  "role": "attendee"
}
```

举办方注册请求：

```json
{
  "username": "new_organizer",
  "password": "123456",
  "role": "organizer"
}
```

注意：mock 注册不会真正写入数据库，也不会校验用户名重复。它只用于测试注册成功后的前端流程，例如提示、跳转、是否进入偏好设置页。

### 6.3 注册后偏好设置测试

临时把 `frontend/src/api/user.js` 的更新资料接口改为：

```js
export function updateUserProfileAPI(data) {
  return request.put('/mock/user/profile', data)
}
```

偏好设置页提交示例：

```json
{
  "gender": "female",
  "tags": ["科技", "音乐", "学术"]
}
```

mock 接口固定返回：

```json
{
  "code": 200,
  "msg": "更新成功",
  "data": null
}
```

前端可据此测试"普通参会者注册后进入偏好设置页、提交后清除临时 token 并回到登录页"的流程。

### 6.4 活动大厅和活动管理测试

临时把 `frontend/src/api/event.js` 的列表接口改为：

```js
export function getEventListAPI(params) {
  return request.get('/mock/event/list', { params })
}
```

C 端活动大厅使用：

```js
getEventListAPI({ scope: 'public', page: 1, size: 10 })
```

只会返回 `status = online` 的活动。

B 端活动管理使用：

```js
getEventListAPI({ scope: 'organizer', page: 1, size: 10 })
```

会返回 draft / online / offline / finished 等多状态活动，方便测试状态标签和卡片样式。

活动详情接口临时改为：

```js
export function getEventDetailAPI(eventId) {
  return request.get(`/mock/event/${eventId}`)
}
```

可测试详情页展示、进度条、地点和时间字段。

### 6.5 Dashboard 测试

临时把 `frontend/src/api/dashboard.js` 改为：

```js
export function getDashboardOverviewAPI() {
  return request.get('/mock/dashboard/overview')

export function getDashboardEventDetailAPI(eventId) {
```

可测试：

- 单活动 AI 预测卡片：`predictedArrivalRate`、`reason`、`suggestion`

## 七、接口清单

### 7.1 认证与用户

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/mock/auth/login` | 返回模拟 token、userId、username、role |
| POST | `/api/v1/mock/auth/register` | 返回模拟注册结果，支持 `role=attendee/organizer` |
| GET | `/api/v1/mock/user/profile?role=attendee` | 返回模拟用户资料 |
| PUT | `/api/v1/mock/user/profile` | 模拟更新性别和偏好标签 |

### 7.2 活动

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/mock/event/list?scope=public&page=1&size=10` | 返回模拟活动分页列表；`scope=public` 只返回 online |
| GET | `/api/v1/mock/event/{eventId}` | 返回模拟活动详情 |
| POST | `/api/v1/mock/event/{eventId}/ai-description` | 返回模拟 AI 活动文案 |

### 7.3 Dashboard

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/mock/dashboard/overview` | 返回核心指标、活动简表和三类图表数据 |
| GET | `/api/v1/mock/dashboard/event/{eventId}` | **新增** 返回单个活动的详细数据指标、图表和签到明细 |
| GET | `/api/v1/mock/dashboard/prediction/{eventId}` | 返回模拟参会率预测 |

### 7.4 推荐

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/mock/recommend/events?page=1&size=3` | 返回模拟推荐活动分页数据 |

### 7.5 票务与核销

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/mock/ticket/purchase` | 返回模拟抢票成功结果 |
| GET | `/api/v1/mock/ticket/my-tickets?status=pending` | 返回模拟我的票夹分页列表 |
| GET | `/api/v1/mock/ticket/{ticketId}` | 返回模拟单张票详情 |
| POST | `/api/v1/mock/ticket/checkin` | 返回模拟签到成功结果 |
| GET | `/api/v1/mock/ticket/event/{eventId}/checkins` | 返回模拟活动签到明细 |

## 九、删除步骤

### 9.1 方案 A（后端 Mock）删除步骤

真实接口联调完成后，按以下步骤删除虚拟接口：

1. 删除 `src/main/java/com/easysign/controller/MockDataController.java`。
2. 从 `src/main/java/com/easysign/config/WebMvcConfig.java` 的 `excludePathPatterns` 中删除：

```java
"/api/v1/mock/**"
```

3. 检查前端 `frontend/src/api/**` 中是否仍有 `/mock/` 路径，全部切回正式接口路径。
4. 删除本文档 `docs/虚拟数据接口说明文档.md`。
5. 运行后端编译和前端构建，确认无残留引用。

### 9.2 方案 B（前端本地 Mock）删除步骤

当需要切换回正式后端接口时，按以下步骤操作：

1. **恢复 `frontend/src/api/dashboard.js`**：
   - 删除文件顶部的 `MOCK_EVENTS`、`MOCK_OVERVIEW`、`MOCK_EVENT_DETAIL_BASE`、`MOCK_PREDICTION` 等本地 Mock 数据常量
   - 将三个 API 函数从 `Promise.resolve(...)` 改回 `request.get(...)` 调用

2. **恢复 `frontend/src/api/auth.js`**：
   - 删除文件顶部的 `MOCK_LOGIN_RESPONSE`、`MOCK_REGISTER_RESPONSE`、`MOCK_PROFILE_RESPONSE` 等本地 Mock 数据常量
   - 将 `loginAPI`、`registerAPI`、`getUserProfileAPI` 从 `Promise.resolve(...)` 改回 `request.post/get(...)` 调用

3. **恢复 `frontend/src/api/event.js`**：
   - 删除文件顶部的 `MOCK_EVENTS` 本地 Mock 数据常量
   - 将所有 API 函数从 `Promise.resolve(...)` 改回 `request.get/post/put/patch/delete(...)` 调用

4. **恢复 `frontend/src/api/ticket.js`**：
   - 删除文件顶部的 `MOCK_TICKETS` 本地 Mock 数据常量
   - 将所有 API 函数从 `Promise.resolve(...)` 改回 `request.get/post(...)` 调用

5. **恢复 `frontend/src/api/user.js`**：
   - 将 `updateUserProfileAPI` 从 `Promise.resolve(...)` 改回 `request.put(...)` 调用

6. 运行前端构建，确认无残留引用。

## 十、注意事项

- 不要在生产环境依赖 `/api/v1/mock/**`。
- 不要把 mock 数据写入数据库初始化脚本。
- 不要在 mock 接口中加入真实鉴权、支付、抢票并发等业务逻辑。
