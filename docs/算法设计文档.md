# 参会率预测算法设计文档

## 一、最终算法定义

### 1.1 预测公式

```
预测率 = 历史签到率 × 0.50 + 热度 × 0.20 + 购票集中度 × 0.20 + 时段因子 × 0.10
```

### 1.2 各因子定义

| 因子 | 权重 | 数据来源 | 计算公式 |
|------|------|----------|----------|
| 历史签到率 | 0.50 | ticket 表（已结束活动） | 该举办方所有已结束活动的 checked_in 总数 / sold_tickets 总数 |
| 热度 | 0.20 | event 表（当前活动） | sold_tickets / total_tickets |
| 购票集中度 | 0.20 | ticket.created_at（当前活动） | 按甲乙丙丁四个时段统计购票分布，加权合成后映射为 0~1 因子 |
| 时段因子 | 0.10 | event.start_time（当前活动） | 根据开始时间所在时段（甲/乙/丙/丁）赋予不同权重 |

#### 购票集中度

按甲乙丙丁四个时段对购票记录分组，各时段计算方式不同：

**时段定义：**

| 时段 | 时间范围 | 说明 |
|------|----------|------|
| 甲 | 周一至周五 00:00-17:59 | 工作日白天，购票行为最"被动" |
| 乙 | 周一至周四 18:00-23:59 | 工作日晚上（不含周五），购票行为较主动 |
| 丙 | 周六、周日 00:00-12:59 | 周末早上，购票行为较主动 |
| 丁 | 周五 18:00-23:59；周六、周日 13:00-23:59 | 其余时间，购票行为最"主动" |

**各时段计算方式：**

| 时段 | 计算指标 | 公式 | 权重 |
|------|----------|------|------|
| 甲 | 覆盖度 | 购票数 / 有购票的天数 | 0.40 |
| 乙 | 覆盖度 + 峰值集中度 | (覆盖度 + 峰值集中度) / 2 | 0.25 |
| 丙 | 覆盖度 + 峰值集中度 | (覆盖度 + 峰值集中度) / 2 | 0.20 |
| 丁 | 峰值集中度 | 单小时最大购票数 / 总购票数 | 0.15 |

> **覆盖度** = 该时段购票总数 / 有购票行为的天数，反映购票在时间轴上的分散程度
> **峰值集中度** = 单小时最大购票数 / 该时段购票总数，反映购票是否集中在某一小时

加权合成总集中度后，按分段映射表转为 0~1 因子：

| 总集中度范围 | 映射因子 |
|-------------|----------|
| ≥ 0.50 | 1.0 |
| ≥ 0.30 | 0.8 |
| ≥ 0.15 | 0.5 |
| ≥ 0.05 | 0.3 |
| < 0.05 | 0.1 |

> **设计逻辑**：甲时段购票者时间不自由（工作日白天），购票分散在不同日子说明活动持续有吸引力，因此用覆盖度衡量；丁时段购票者时间自由（周末/周五晚），某一小时突然大量购票说明有外部事件触发，签到意愿更强，因此用峰值集中度衡量。乙、丙介于两者之间，兼顾覆盖度和峰值集中度。

#### 时段因子

根据活动开始时间所在时段赋予不同权重：

| 时段 | 时间范围 | 因子值 |
|------|----------|--------|
| 甲 | 周一至周五 00:00-17:59 | 0.3 |
| 乙 | 周一至周四 18:00-23:59 | 0.5 |
| 丙 | 周六、周日 00:00-12:59 | 0.6 |
| 丁 | 周五 18:00-23:59；周六、周日 13:00-23:59 | 0.9 |

> **设计逻辑**：甲时段（工作日白天）举办的活动，目标人群时间受限，到场难度大；丁时段（周末/周五晚）举办的活动，目标人群时间充裕，到场概率更高。

    // 1. 历史签到率：该举办方所有已结束活动的总签到数 / 总已售票数
    double historyRate = getHistoryCheckinRate(organizerId);
    
    // 2. 热度：当前活动已售票数 / 总票数

    // 3. 购票集中度：按甲乙丙丁四个时段分别计算覆盖度/峰值集中度，加权合成后映射为 0~1 因子

## 二、设计历程

以下按时间线记录算法从初版到最终定稿的完整迭代过程，使用 🤖（AI）和 👤（人类）标记区分双方在设计过程中的角色与贡献。

### 2.1 第一轮：三因子模型的提出

**背景**

PRD 文档要求实现参会率预测功能，并给出了三个候选特征：

- 特征1：该类活动历史平均签到率
- 特征2：距离活动开始时间
- 特征3：报名人数与总限额的比例（热度）

> 🤖 **AI 提出初始方案**
>
> 建议采用三因子加权模型：
>
> ```
> 预测率 = 历史平均签到率 × 0.5 + 距离系数 × 0.2 + 热度 × 0.3
> ```
>
> 其中距离系数根据距开始天数分段映射：≤1 天为 0.9，2~3 天为 0.8，4~7 天为 0.7，8~14 天为 0.5，>14 天为 0.3。

> 👤 **人类提出质疑**
>
> "距离开始时间这个参数，如果活动甲 4.1 卖票、5.1 开始，系数会低；活动乙 4.30 卖票、5.1 开始，系数会高。但如果活动甲从 4.1 卖到 4.30，每天卖的数量不一样，又怎么算？这个太复杂了。"

> 🤖 **AI 回应**
>
> 解释系统数据库不支持记录"每天卖了多少张"，只有 sold_tickets 总量，没有 daily_sales 表，所以无法还原购票曲线。建议直接用当前时间到 start_time 的天数查表。

> 👤 **人类进一步质疑**
>
> "语义完全不正确——活动前一天大家的签到率都是一样的，这个系数没用。"

> 🤖 **AI 承认漏洞**
>
> 承认该系数在同一时间点对所有活动没有区分度，但建议保留作为"微调"参数。

> 👤 **人类最终判断**
>
> "直接舍弃。"

✅ **共同决策**：排除距离系数，将权重重新分配给剩余两个特征。

### 2.2 第二轮：两因子简化模型

> 🤖 **AI 提出简化方案**
>
> ```
> 预测率 = 历史签到率 × 0.6 + 热度 × 0.4
> ```
>
> 代码中保留距离系数字段但注释说明"当前版本暂不使用"。

> 👤 **人类进一步思考**
>
> "还有什么可能影响的因素，除了这两个？"

> 🤖 **AI 列出候选特征**
>
> 基于系统现有数据字段，列出可用的额外特征：
>
> - 工作日/周末因子：start_time 的星期几
> - 时段因子：start_time 的上午/下午/晚上
> - 距今天数：可简化为"是否 3 天内"的二元因子

> 👤 **人类决策**
>
> "那肯定因子越多越好，越细，起码体现我考虑到了。历史签到率是这类活动的，热度是人数/总票数，周末因子是是否是周末，时段因子是早中晚，这样？"

✅ **共同决策**：扩展为四因子模型，加入周末因子和时段因子。

**2.3 第三轮：购票集中度特征的引入（人类创新）**

**背景**

在决定加入购票集中度特征后，需要进一步明确其具体计算方式。

> 👤 **人类提出创新想法**
>
> "购票系统里是不是存着所有用户买票的时间？如果这个时间大体是平缓的，说明这个活动可能经过理性决策；如果是某一个节点很多人一起买票，说明可能有什么特别值得关注的地方，签到率就会变高。"

> 🤖 **AI 评估**
>
> 确认这个想法逻辑成立，且系统数据库的 ticket 表确实有 created_at 字段（购票时间），技术上可行。建议将"购票集中度"作为一个新特征加入模型，并给出三种实现方案：
> 1. 标准差法（越大越集中）
> 2. 峰度法（越高越集中在某几天）
> 3. 最后 3 天售票占比法（最简单）

> 👤 **人类确认**
>
> 确认 ticket 表有 created_at 字段，决定采用这个特征。

✅ **共同决策**：将购票集中度加入模型，替换周末因子（因周末因子区分度有限）。

---

> 👤 **人类进一步细化**
>
> "购票集中度不能只看一个维度。你想，一个人工作日白天买票，说明他时间不自由，买票可能是抽空做的，决策比较随意；但如果是周末晚上买票，说明他时间自由，买票是认真考虑过的。我建议把一天分成四个时段：甲、乙、丙、丁，甲最不自由，丁最自由。不同时段对购票集中度的含义不一样。"

> 🤖 **AI 理解并补充**
>
> "明白了。甲的购票行为最'被动'，所以甲的集中度应该用覆盖度来衡量——购票分散在不同日子，说明活动持续有吸引力；而丁的购票行为最'主动'，所以丁的集中度应该用峰值集中度来衡量——某个小时突然大量购票，说明有外部事件触发，签到意愿更强。乙和丙介于中间，兼顾两者。"

> 👤 **人类确认**
>
> "对，就是这个意思。甲看广度，丁看高峰。那算出来之后呢？"

> 🤖 **AI 回应**
>
> "算出来的总集中度是一个连续值，需要映射到 0~1 区间才能参与加权。建议用分段映射表：大于等于 0.50 映射为 1.0，大于等于 0.30 映射为 0.8，大于等于 0.15 映射为 0.5，大于等于 0.05 映射为 0.3，小于 0.05 映射为 0.1。"

> 👤 **人类确认**
>
> "可以，这样每个活动都能得到一个 0~1 的购票集中度因子。就这么定。"

✅ **共同决策**：购票集中度按时段（甲乙丙丁）分别计算，甲侧重覆盖度，丁侧重峰值集中度，乙丙兼顾两者，最终通过分段映射表转为 0~1 因子。

### 2.4 最终敲定：四因子加权模型

经过三轮迭代讨论，最终确定四个特征及其权重：

| 因子 | 权重 | 提出者 | 理由 |
|------|------|--------|------|
| 历史签到率 | 0.50 | PRD 文档要求 | 最可靠的预测依据，反映举办方基本盘 |
| 热度 | 0.20 | PRD 文档要求 | 反映当前活动受欢迎程度 |
| 购票集中度 | 0.20 | 👤 人类创新提出 | 反映购票行为的时序特征，体现用户真实兴趣 |
| 时段因子 | 0.10 | 🤖 AI 建议 + 👤 人类确认 | 反映不同时段活动的到场概率差异 |

> 🤖 **AI 提供最终公式**
>
> ```
> 预测率 = 历史签到率 × 0.50 + 热度 × 0.20 + 购票集中度 × 0.20 + 时段因子 × 0.10
> ```

> 👤 **人类确认**
>
> "敲定。"

## 三、人机协作总结

### 3.1 角色分工

| 角色 | 核心贡献 | 具体体现 |
|------|----------|----------|
| 人类（👤） | 业务直觉与逻辑批判 | 发现距离系数的逻辑漏洞、提出购票集中度这一创新特征、最终决策权 |
| AI（🤖） | 方案生成与技术评估 | 提供初始模型框架、评估特征可行性、给出代码实现、记录迭代过程 |
| 共同 | 模型结构确定 | 最终四因子结构、权重分配、各因子计算规则 |

### 3.2 设计原则

1. **可解释性优先**：每个因子都有明确的业务含义，能在答辩时讲清楚"为什么用这个因子"
2. **数据可行性**：所有因子都基于系统现有数据库字段，无需新增数据采集
3. **渐进迭代**：从三因子 → 两因子 → 四因子，每一步都有明确的决策依据
