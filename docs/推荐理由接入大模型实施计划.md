# 推荐理由接入大模型 — 实施计划

> 当前 `RecommendServiceImpl.java` 已实现加权排序算法，推荐理由为固定文案。
> 计划引入大模型（LLM）生成个性化推荐理由，作为可选增强层。

---

## 一、现状分析

### 现有推荐理由实现

`RecommendServiceImpl.toEventResponseWithReason()` 中的逻辑：

| 条件 | 当前 reason |
|------|------------|
| `hasTagMatch == true` | `"根据你的偏好标签推荐"` |
| `hasTagMatch == false` | `"热门活动推荐"` |

**问题：** 所有用户的推荐理由完全一致，缺乏个性化和说服力。

### 现有 AI 基础设施

`com.easysign.ai` 包包含 `AiService` 接口、`MockAiService` 和 `FeatureEngine`，当前未被推荐服务调用。

### 设计文档已有约定

> **AI 的定位：增强推荐理由** — 加权排序负责选活动，LLM 仅生成文案，不可用时降级为固定文案。

---

## 二、设计决策

### 核心原则

| 原则 | 说明 |
|------|------|
| **加权排序不变** | LLM 仅负责文案，不参与排序决策 |
| **可选增强层** | AI 不可用时降级为固定文案 |
| **单活动粒度** | 每次调用生成单条推荐理由，降级粒度细 |
| **Mock 先行** | 先实现模板化 Mock，后续接入 DeepSeek |
| **本地缓存** | 推荐理由缓存在本地，TTL=5min，减少重复调用 |
| **配置驱动** | LLM 开关/地址/超时等通过 `application.properties` 控制 |

### 缓存策略

```
缓存 key: "recommend:reason:{userId}:{eventId}"
缓存方案: Caffeine 本地缓存（Spring Boot 默认支持），不引入 Redis
TTL: 5 分钟
```

同一用户 5 分钟内再次请求推荐 → 直接命中缓存，不调 LLM。


### 3.2 MockAiService 模板逻辑

| 条件 | Mock 文案模板 |
|------|--------------|
| 标签匹配 + 售票率 > 0 | `"根据你的【{标签}】偏好，推荐【{title}】，售票率已达 {sellRate}%"` |
| 标签匹配 + 售票率 = 0 | `"根据你的【{标签}】偏好推荐【{title}】"` |
| 无标签匹配 + 售票率 > 0 | `"热门推荐【{title}】，售票率 {sellRate}%"` |
| 无标签匹配 + 售票率 = 0 | `"热门推荐【{title}】"` |

### 3.3 DeepSeekAiService 架构（真实接入）

新增 `DeepSeekAiService implements AiService`，与 MockAiService 并列，通过 `@ConditionalOnProperty` 按配置切换。

**HTTP 客户端：** 使用 Hutool `HttpUtil`（项目已有 Hutool 依赖），避免新增依赖。

**Prompt 构造：** 新建 `RecommendPromptBuilder`（独立于 `FeatureEngine`，各自关注不同场景）。

**响应解析：** DeepSeek 返回 OpenAI 兼容格式：

```
HTTP Response JSON:
{
  "choices": [{
    "message": {
      "content": "你最近关注的科技和电竞领域有场AI技术沙龙..."
    }
  }]
}
```

**Prompt 模板：**

```
你是一个高校活动推荐助手。请根据以下信息生成一句简洁、自然的推荐理由（30字以内）：

用户偏好标签：["科技", "电竞"]
活动标题：AI 技术沙龙
活动标签：["科技", "讲座"]
售票率：75%

要求：语气亲切，不要客套话，直接说明推荐原因。
```

**核心逻辑伪代码：**

```java
@Autowired
private AiService aiService;

@Autowired
private CacheManager cacheManager;

private String generateReason(Long userId, Event event, boolean hasTagMatch,
                               List<String> userTags, double sellRate) {
    // 缓存检查
    Cache cache = cacheManager.getCache("recommendReason");
    String cacheKey = userId + ":" + event.getId();
    String cached = cache.get(cacheKey, String.class);
    if (cached != null) return cached;

    try {
        String userTagsJson = /* userTags 转 JSON */;
        String aiReason = aiService.generateRecommendReason(
            userTagsJson, event.getTitle(), event.getTags(), sellRate, hasTagMatch);
        if (aiReason != null && !aiReason.isBlank()) {
            cache.put(cacheKey, aiReason);
            return aiReason;
        }
    } catch (Exception e) {
        log.warn("AI 推荐理由生成失败，降级为固定文案: eventId={}", event.getId(), e);
    }
    return hasTagMatch ? "根据你的偏好标签推荐" : "热门活动推荐";
}
```

## 六、降级与容错策略

| 场景 | 行为 |
|------|------|
| MockAiService 未注入 / 启动失败 | Spring 启动报错，不视为运行时降级 |
| AI 调用抛出任意异常 | catch + log warn + 降级为固定文案 |
| AI 返回 null 或空字符串 | 同上 |
| AI 返回文案超长 | 文案长度校验 + 降级或截断 |
| 真实 LLM API 超时 | try-catch + `CompletableFuture` 500ms 超时 |
| 真实 LLM API 连续失败 N 次 | log warn，后续请求直接跳过（熔断简化版） |
| 缓存不可用 | catch + 忽略，直接调 AI |
