## 一、设计决策

| 决策项 | 结论 | 说明 |
|--------|------|------|
| 选座是否可选 | **是，由举办方决定** | `event` 表新增 `has_seats` 字段，默认 false。开启后座位布局为固定模板 |
| 座位布局 | **固定模板** | 不提供举办方自定义排/列数。前后端约定统一座位矩阵（如 10×10），前端 Canvas 渲染 |
| 选座与抢票是否拆分 | **拆分，两步操作** | 用户先点击座位选中（纯前端本地高亮，不触发后端请求），再点击"立即抢票"按钮调用抢票接口。后端在抢票时校验座位是否仍可用，不可用时返回 4100 并由前端刷新座位矩阵 |
| 防碰撞 | **仅依赖数据库原子操作** | 不做 WebSocket 锁定广播。并发冲突时依赖 `UPDATE seat SET status='sold' WHERE id=? AND status='available'` 的原子 UPDATE 保证最终一致性。冲突方收到 4100 后前端自动刷新座位图 |
| 一人一票 | **不变** | 现有 `uk_event_user` 唯一约束继续生效 |

## 二、数据库变更

### 2.1 `event` 表新增字段

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `has_seats` | TINYINT(1) | NOT NULL DEFAULT 0 | 是否开启选座：0=不开启，1=开启。仅 draft/offline 状态可修改 |

**ALTER SQL**：

```sql
ALTER TABLE `event`
  ADD COLUMN `has_seats` TINYINT(1) NOT NULL DEFAULT 0
  COMMENT '是否开启选座：0=不开启，1=开启';
```

### 2.2 新增 `seat` — 座位表

座位矩阵为固定模板（默认 10 行 × 10 列 = 100 座）。活动开启选座时，系统自动为该活动生成全部座位记录。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 主键 |
| `event_id` | BIGINT | NOT NULL | 关联活动 ID（逻辑关联 `event.id`） |
| `seat_row` | INT | NOT NULL | 排号（从 1 开始） |
| `seat_col` | INT | NOT NULL | 列号（从 1 开始） |
| `seat_label` | VARCHAR(20) | NOT NULL | 座位展示标签，如 "1-1"、"10-10" |
| `status` | ENUM('available','sold') | NOT NULL DEFAULT 'available' | 座位状态：可选 / 已售出 |

**索引**：

```sql
UNIQUE INDEX `uk_event_seat` (`event_id`, `seat_row`, `seat_col`),
INDEX `idx_event_status` (`event_id`, `status`)
```

**建表 SQL**：

```sql
CREATE TABLE `seat` (
  `id`          BIGINT                                   PRIMARY KEY AUTO_INCREMENT  COMMENT '主键',
  `event_id`    BIGINT                                   NOT NULL                    COMMENT '关联活动ID',
  `seat_row`    INT                                      NOT NULL                    COMMENT '排号',
  `seat_col`    INT                                      NOT NULL                    COMMENT '列号',
  `seat_label`  VARCHAR(20)                              NOT NULL                    COMMENT '座位标签，如"1-1"',
  `status`      ENUM('available','sold')                 NOT NULL DEFAULT 'available' COMMENT '座位状态：available=可选, sold=已售出',
  UNIQUE INDEX `uk_event_seat` (`event_id`, `seat_row`, `seat_col`),
  INDEX `idx_event_status` (`event_id`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='座位表';
```

### 2.3 `ticket` 表新增字段

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `seat_id` | BIGINT | DEFAULT NULL | 关联座位 ID。NULL 表示无选座活动或未选座 |

**ALTER SQL**：


```
3. 【新增】若 hasSeats = true，在插入 ticket 后原子更新 seat：
```

### 3.3 新增 WebSocket 端点

#### 3.3.1 连接端点

```
ws://{host}/ws/seat/{eventId}
```

**说明**：客户端连接后，服务端推送该活动下所有座位的实时状态变更。

**认证**：通过 URL 参数携带 token：
```
ws://{host}/ws/seat/{eventId}?token={jwt_token}
```

#### 3.3.2 消息协议

所有消息使用 JSON 格式。**当前版本 WebSocket 仅用于服务端→客户端单向推送，客户端不发送任何消息**。

##### 服务端 → 客户端

**广播座位已售出**（抢票成功后推送给该活动所有已连接客户端）：
```json
{
  "type": "seat_sold",
  "seatId": 1
}
```

**全量同步**（客户端首次连接时，服务端向该客户端发送当前所有座位状态）：
```json
{
  "type": "seat_sync",
  "data": {
    "seats": [
      { "seatId": 1, "status": "available" },
      { "seatId": 2, "status": "sold" },
      { "seatId": 3, "status": "available" }
    ]
  }
}
```

**说明**：`seat_sync` 中的 `status` 仅含 `available` 与 `sold`。不存在"锁定中"的中间态——用户选中座位仅为前端本地高亮，不通知服务端。

```java
private static final int DEFAULT_ROWS = 10;

public void initSeats(Long eventId) {
    List<Seat> seats = new ArrayList<>();
    for (int row = 1; row <= DEFAULT_ROWS; row++) {
```

### 5.2 连接管理

按 `eventId` 分组管理 WebSocket 会话，维护 `Map<Long, Set<WebSocketSession>>`。

```java
@Component
public class SeatWebSocketHandler extends TextWebSocketHandler {

    // eventId → 该活动所有连接的 session 集合
    private final ConcurrentHashMap<Long, Set<WebSocketSession>> eventSessions = new ConcurrentHashMap<>();

    @Override
    public void afterConnectionEstablished(WebSocketSession session) {
        Long eventId = (Long) session.getAttributes().get("eventId");
        eventSessions.computeIfAbsent(eventId, k -> ConcurrentHashMap.newKeySet()).add(session);

        // 发送全量座位状态同步
        sendSeatSync(session, eventId);
    }

    @Override
    public void afterConnectionClosed(WebSocketSession session, CloseStatus status) {
        Long eventId = (Long) session.getAttributes().get("eventId");
        Set<WebSocketSession> sessions = eventSessions.get(eventId);
        if (sessions != null) {
            sessions.remove(session);
            if (sessions.isEmpty()) {
                eventSessions.remove(eventId);
            }
        }
    }

    // 向某活动所有连接广播消息
    public void broadcastToEvent(Long eventId, String jsonMessage) {
        Set<WebSocketSession> sessions = eventSessions.get(eventId);
        if (sessions != null) {
            TextMessage msg = new TextMessage(jsonMessage);
            for (WebSocketSession session : sessions) {
                if (session.isOpen()) {
                    try {
                        session.sendMessage(msg);
                    } catch (IOException e) {
                        log.warn("WebSocket 推送失败: sessionId={}", session.getId());
                    }
                }
            }
        }
    }
}
```

### 5.3 当前版本广播逻辑

当前版本 WebSocket 仅承担两项职责：

1. **连接时全量同步**：客户端建立 WebSocket 连接后，服务端立即发送 `seat_sync` 消息，包含该活动所有座位的当前状态（`available` / `sold`）。
2. **售出时增量广播**：当任一用户通过 REST 抢票接口成功购买某座位后，`TicketServiceImpl` 主动调用 `broadcastToEvent()` 向该活动所有已连接客户端广播 `seat_sold` 消息。收到消息的客户端将该座位标记为不可选。

此设计的关键保障：并发冲突的最终一致性由抢票接口（REST）中的原子 SQL 保证——

```sql
UPDATE seat SET status = 'sold' WHERE id = ? AND status = 'available'
```

同一座位最多只有一人能执行成功（`affected rows = 1`）。失败方会收到 HTTP 4100 错误（"该座位已被选走"），前端收到该错误后应重新调用 `GET /seats` 刷新座位矩阵。

> 此方案存在短时不一致窗口：用户 A 抢票成功后，从 WebSocket `seat_sold` 广播到用户 B 接收到之间存在网络延迟。在此期间用户 B 可能选中同一座位并点击抢票，然后收到 4100 错误。这是可接受的设计取舍——用户 B 会看到提示并自动刷新，不会出现一票多卖的数据错误。

### 6.2 座位矩阵 Canvas 渲染

在 C 端活动详情页新增 `SeatCanvas.vue` 组件：

**组件结构**：
```
SeatCanvas.vue
├── <canvas> 座位矩阵（10×10 网格）
│   ├── 可选座位（绿色/灰色）
│   ├── 锁定中（红色，他人正在看）
│   ├── 已售出（深灰，不可点击）
│   └── 当前选中（蓝色高亮边框）
├── 已选座位信息栏
│   ├── 座位号：如 "5-3"
│   └── "立即抢票"按钮（带 seatId 参数调用 purchase）
└── WebSocket 连接管理（mounted 时连接，unmounted 时断开）
```

**交互流程**：
1. 用户进入活动详情页，`mounted` 时调用 `GET /api/v1/event/{eventId}/seats` 获取全量座位状态。
2. 前端渲染 Canvas 网格。各状态颜色：
   - `available`：浅绿色（#a8e6cf）
   - `locked`：红色（#ff6b6b），仅展示不可点击
   - `sold`：深灰色（#888888），不可点击
3. 建立 WebSocket 连接 `ws://{host}/ws/seat/{eventId}`。
4. 用户点击可选座位 → Canvas 高亮该座位为蓝色边框（本地），同时座位信息栏显示座位号。
5. 用户点击"立即抢票"→ 携带 `seatId` 调用 `POST /api/v1/ticket/purchase`。
6. 抢票成功：座位变灰，WebSocket 广播 `seat_sold` 给所有人。
7. 抢票失败（如座位已被他人抢走）：弹出提示"该座位已被选走"，刷新座位矩阵。

### 6.3 前端 WebSocket 管理

在 `SeatCanvas.vue` 中建立 WebSocket 连接：

```javascript
// 伪代码
data() {
  return {
    socket: null,
    seats: [],
    selectedSeatId: null
  }
},

async mounted() {
  // 1. 拉取全量座位
  const res = await getEventSeats(this.eventId);
  this.seats = res.data.seats;

  // 2. 建立 WebSocket
  this.connectWebSocket();
},

methods: {
  connectWebSocket() {
    const token = localStorage.getItem('token');
    this.socket = new WebSocket(`ws://${host}/ws/seat/${this.eventId}?token=${token}`);

    this.socket.onmessage = (event) => {
      const msg = JSON.parse(event.data);
      switch (msg.type) {
        case 'seat_locked':
          this.updateSeatStatus(msg.seatId, 'locked');
          break;
        case 'seat_unlocked':
          this.updateSeatStatus(msg.seatId, 'available');
          break;
        case 'seat_sold':
          this.updateSeatStatus(msg.seatId, 'sold');
          // 如果当前用户选中的座位被卖出，清除选中
          if (this.selectedSeatId === msg.seatId) {
            this.selectedSeatId = null;
          }
          break;
        case 'seat_sync':
          this.seats = msg.data.seats;
          break;
      }
    };
  },

  selectSeat(seatId) {
    // 本地标记选中
    this.selectedSeatId = seatId;
  },

  async purchaseWithSeat() {
    const res = await purchaseTicket({
      eventId: this.eventId,
      seatId: this.selectedSeatId
    });
    // 处理结果...
  }
},

beforeUnmount() {
  if (this.socket) {
    this.socket.close();
  }
}
```

## 八、向后兼容性说明

| 场景 | 行为 |
|------|------|
| 现存活动（`has_seats` 为默认值 0） | 完全不受影响，所有现有接口行为不变 |
| `seat_id = NULL` 的 ticket 记录 | 正常展示，票夹/签到明细中 `seatLabel = null` |
| 前端未传 `seatId` 但活动有选座 | 后端返回 4000（该活动需要选择座位） |
| 前端传了 `seatId` 但活动无选座 | 后端忽略 `seatId`，按原逻辑处理 |

## 九、防碰撞机制（后续迭代预留）

当前版本不实现防碰撞，但架构上已预留扩展点：

1. 抢票接口中 `seat_id` 的原子更新已使用 `WHERE status='available'`，具备基础并发安全。
2. WebSocket 单向广播通道已建立（`seat_sold`），后续如需引入锁定机制，可扩展：
   - `seat` 表新增 `locked_by`、`locked_at` 字段，`status` 枚举增加 `'locked'`。
   - WebSocket 协议增加 `seat_lock`/`seat_unlock`（C→S）和 `seat_locked`/`seat_unlocked`（S→All）消息对。
   - 服务端引入 Redis 分布式锁（Redisson）实现毫秒级防碰撞。
3. 上述改造不影响当前 REST 接口签名，属于纯增量变更。
