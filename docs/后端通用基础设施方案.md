## 二、通用基础设施模块（按实施优先级排列）

### 2.1 通用响应体 `Result<T>`

**目的**：统一全项目 API 返回值结构，前端统一解析。

**核心内容**：

```java
// 泛型响应体
public class Result<T> {
    private int code;           // 业务码
    private String msg;         // 提示信息
    private T data;             // 数据

    // 静态工厂方法
    public static <T> Result<T> success(T data);
    public static <T> Result<T> success(String msg, T data);
    public static <T> Result<T> error(int code, String msg);
}
```

**业务码枚举** `BizCode`：

| code | 含义 | 说明 |
|------|------|------|
| 200 | 成功 | |
| 4000 | 请求参数错误 | 参数缺失、格式非法、校验失败 |
| 4001 | 认证失败 | 未登录 / token 无效 / 过期 |
| 4002 | 权限不足 | 角色不符（如 attendee 调 organizer 接口） |
| 4003 | 资源不存在 | 查询的记录不存在 |
| 4004 | 资源冲突 | 重复操作（如重复抢票） |
| 4100 | 业务逻辑错误 | 通用业务失败（如活动已下线） |
| 4101~4107 | 签到专用 | 见接口文档 |
| 429 | 请求过于频繁 | 限流触发 |
| 5000 | 服务器内部错误 | 未预期异常 |

### 2.2 全局异常处理 `@RestControllerAdvice`

**目的**：集中捕获异常，返回统一格式的 `Result`，避免每个 Controller 写 try-catch。

**处理链**：

```
请求 → Controller → Service → 抛出异常
                          ↓
          @RestControllerAdvice 拦截
                          ↓
   ┌──────── 异常类型判断 ────────┐
   ↓                              ↓
BizException               其他异常
(code + msg)               (5000 + 内部错误)
   ↓                              ↓
   └──────── Result 返回 ─────────┘
```

**需捕获的异常类型**：

| 优先级 | 异常类型 | 返回 code | 说明 |
|--------|---------|-----------|------|
| 1 | `BizException` | 自定义 | 业务异常，含 code 和 msg |
| 2 | `MethodArgumentNotValidException` | 4000 | `@Valid` 参数校验失败 |
| 3 | `ConstraintViolationException` | 4000 | `@PathVariable`/`@RequestParam` 校验失败 |
| 4 | `MissingServletRequestParameterException` | 4000 | 必填参数缺失 |
| 5 | `HttpMessageNotReadableException` | 4000 | 请求体格式错误（如 JSON 解析失败） |
| 6 | `Exception`（兜底） | 5000 | 未预期异常 |

### 2.3 自定义业务异常 `BizException`

```java
public class BizException extends RuntimeException {
    private final int code;
    private final String msg;

    public BizException(int code, String msg) {
        super(msg);
        this.code = code;
        this.msg = msg;
    }

    public BizException(BizCode bizCode) {
        this(bizCode.getCode(), bizCode.getMsg());
    }
}
```

### 2.4 JWT 认证基础设施

**需要新增的组件**：

| 组件 | 文件 | 说明 |
|------|------|------|
| JWT 工具类 | `JwtUtil.java` | 生成 token、解析 token、校验过期 |
| 用户上下文 | `UserContext.java` | ThreadLocal 存储当前请求用户信息 |
| JWT 拦截器 | `JwtInterceptor.java` | 从 Authorization 头提取 token → 解析 → 放入 UserContext |
| Web 配置 | `WebMvcConfig.java` | 注册拦截器，配置放行路径 |
| 认证注解 | `@RequireRole("organizer")` | 可选，简化权限校验 |

**JWT Token 内容**：

```json
{
  "userId": 1,
  "username": "zhangsan",
  "role": "attendee"
}
```

**注册后画像补全说明**：`POST /api/v1/auth/register` 返回的 token 可被前端临时保存。仅当注册角色为 `attendee`（普通参会者）时，前端才进入偏好设置页并调用 `PUT /api/v1/user/profile` 写入 `gender/tags`；`organizer`（活动举办方）注册后不进入偏好设置页。画像提交成功后前端清除该临时登录态并回到登录页；后端无需新增特殊会话机制。

**放行路径白名单**：

```
POST /api/v1/auth/login
POST /api/v1/auth/register
GET  /api/v1/event/list             (scope=public 时)
GET  /api/v1/event/{eventId}
GET  /api/v1/recommend/events        (已登录时可选)
```

**UserContext 设计**：

```java
public class UserContext {
    private static final ThreadLocal<UserInfo> CONTEXT = new ThreadLocal<>();

    public static void set(UserInfo user);
    public static UserInfo get();
    public static Long getUserId();
    public static String getUsername();
    public static String getRole();
    public static boolean isLoggedIn();
    public static boolean hasRole(String role);
    public static void clear();          // 请求结束后清理，防止内存泄漏
}
```

> **为什么用 ThreadLocal 而非 Request Attribute？** Service 层不需要依赖 `HttpServletRequest`，ThreadLocal 可以做到"零侵入"地获取当前用户信息，Service 层的 `service` 方法签名不必传入 `userId` 参数。

**拦截器链**：

```java
// WebMvcConfig.java
@Override
public void addInterceptors(InterceptorRegistry registry) {
    registry.addInterceptor(jwtInterceptor)
            .addPathPatterns("/api/v1/**")
            .excludePathPatterns(
                "/api/v1/auth/login",
                "/api/v1/auth/register",
                "/api/v1/event/list",     // scope=public 时放行，逻辑在 Controller 判断
                "/api/v1/event/{eventId}"
            );
}
```

> **注意**：`/api/v1/event/list` 和 `/api/v1/event/{eventId}` 虽然是公开接口，但拦截器放行后，Controller 层需要通过 `@RequestHeader(value = "Authorization", required = false)` 判断是否已登录，scope=organizer 时要求登录。我们在拦截器层面放行（不阻止），在 Controller 层面动态判断。

### 2.5 MyBatis-Plus 配置（重点：从 MyBatis 升级）

**升级步骤**：

1. **pom.xml 替换依赖**：将 `mybatis-spring-boot-starter` 替换为 `mybatis-plus-spring-boot3-starter`
2. **调整配置文件**：`mybatis.mapper-locations` → `mybatis-plus.mapper-locations`
3. **配置分页插件**：`PaginationInnerInterceptor`
4. **配置自动填充**：`MetaObjectHandler`（处理 `created_at`, `updated_at`）
5. **Entity 继承 Model**：三张实体类实现 `BaseMapper<T>`

**核心配置类**：

```java
@Configuration
@MapperScan("com.example.testticketbackend.mapper")
public class MyBatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 分页插件（关键：文档要求所有列表接口分页）
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }

    @Bean
    public MybatisPlusPropertiesCustomizer plusPropertiesCustomizer() {
        return props -> props.setMapperLocations(new String[]{"classpath:mapper/*.xml"});
    }
}
```

**自动填充处理器**：

```java
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {
    @Override
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createdAt", LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updatedAt", LocalDateTime.class, LocalDateTime.now());
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updatedAt", LocalDateTime.class, LocalDateTime.now());
    }
}
```

**实体类示例**（以 Event 为例）：

```java
@Data
@TableName("event")
public class Event {
    @TableId(type = IdType.AUTO)
    private Long id;
    private Long organizerId;
    private String title;
    private String description;
    private String location;
    private LocalDateTime startTime;
    private LocalDateTime endTime;
    private Integer totalTickets;
    private Integer soldTickets;
    private String status;           // draft / online / offline / finished

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createdAt;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updatedAt;
}
```

### 2.7 跨域配置 CORS

```java
@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("*")
                .allowedMethods("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true);
    }
}
```

### 2.9 AI 禁飞区抽象层（MVP 占位）

| 功能 | 接口 | 占位实现 | 最终实现 |
|------|------|---------|---------|
| 一键生成文案 | `AiService.generateDescription(title)` | 返回硬编码文案 | 调用 LLM API |
| 参会率预测 | `AiService.predictArrivalRate(eventId)` | 返回随机值 | 特征工程 + LLM |
| 活动推荐 | `RecommendService.recommend(userId)` | 按热度排序 | 加权排序算法 |

**PRD 要求的特征工程类 `FeatureEngine`**：

```java
@Component
public class FeatureEngine {
    /**
     * 计算活动基准到达率
     * 特征因素：同类活动历史到达率、当前热度（sold/total）、距开始时间等
     */
    public double calculateBaseRate(Event event) {
        // 1. 查询同类活动历史到达率（按 tags 匹配）
        // 2. 计算当前售票率
        // 3. 综合加权得出基准分
        return 0.85;
    }

    /**
     * 拼接 Prompt（用于最终 LLM 调用）
     */
    public String buildPredictionPrompt(Event event, double baseRate) {
        return String.format("活动「%s」当前售票率 %.0f%%，历史同类到达率 82%%，基准得分 %.2f，请预测参会到达率并给出建议",
                event.getTitle(), 
                (double) event.getSoldTickets() / event.getTotalTickets() * 100,
                baseRate);
    }
}
```
