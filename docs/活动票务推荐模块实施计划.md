#### 9.2 关键业务逻辑

| 方法 | 校验链 | 说明 |
|------|--------|------|
| createEvent | ① userId 存在 → ② startTime > now → ③ endTime == null \|\| endTime > startTime → ④ totalTickets 在 [1,99999] → ⑤ 插入 event，status='draft' | 时间字符串用 `LocalDateTime.parse(startTime, DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"))` 解析 |

| getEventById | eventId 存在？不存在抛 4003 | 查不到直接抛 BizException |
| updateEvent | ① event 存在且是发布者 → ② finished 不可改 → ③ online 不可改 totalTickets → ④ draft/offline 改 totalTickets 需 ≥ soldTickets → ⑤ **时间校验（见下方详细说明）** | 每个字段独立判断，传入 null 表示不修改 |

| deleteEvent | ① event 存在且是发布者 → ② 当前状态不是 online → ③ 物理删除 event → ④ UPDATE ticket SET status='invalid' WHERE event_id=? | 需 `@Transactional` 保证原子性 |

#### 9.3 时间校验工具方法

```java
// 在 EventServiceImpl 中用到的私有方法
private LocalDateTime parseDateTime(String dateTimeStr) {
    return LocalDateTime.parse(dateTimeStr, DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"));
}

private void validateStartTime(LocalDateTime startTime) {
    if (startTime.isBefore(LocalDateTime.now())) {
        throw new BizException(4000, "开始时间不能早于当前时间");
    }
}

private void validateEndTime(LocalDateTime startTime, LocalDateTime endTime) {
    if (endTime != null && !endTime.isAfter(startTime)) {
        throw new BizException(4000, "结束时间不能早于开始时间");
    }
}
```

#### 9.4 updateEvent 中 startTime / endTime 跨字段比较逻辑

接口文档 4.4 要求：当同时修改 startTime 和 endTime 时，比较新值；否则 compare 修改的字段与现有字段。

```java
public void updateEvent(Long userId, Long eventId, UpdateEventRequest req) {
    // 1. 校验 event 存在且当前用户是发布者
    Event event = eventMapper.selectById(eventId);
    if (event == null) throw new BizException(4003, "活动不存在");
    if (!event.getOrganizerId().equals(userId)) throw new BizException(4002, "权限不足");
    if ("finished".equals(event.getStatus())) throw new BizException(4100, "活动已结束，不可修改");
    
    // 2. online 状态下不可修改 totalTickets
    if ("online".equals(event.getStatus()) && req.getTotalTickets() != null) {
        throw new BizException(4100, "活动已上线，不可修改门票总数");
    }
    
    // 3. draft/offline 改 totalTickets 需校验 >= soldTickets
    if (req.getTotalTickets() != null && req.getTotalTickets() < event.getSoldTickets()) {
        throw new BizException(4000, "门票总数不能小于已售数量");
    }
    
    // 4. ⭐ startTime / endTime 跨字段比较
    // 规则：
    //   - 同时修改 startTime 和 endTime → 比较新 startTime 与新 endTime
    //   - 只修改 startTime（endTime 不变）→ 比较新 startTime 与现有 endTime
    //   - 只修改 endTime（startTime 不变）→ 比较现有 startTime 与新 endTime
    //   - 均不修改 → 跳过
    
    LocalDateTime newStartTime = event.getStartTime();  // 默认使用现有值
    LocalDateTime newEndTime = event.getEndTime();      // 默认使用现有值
    
    if (req.getStartTime() != null) {
        newStartTime = parseDateTime(req.getStartTime());
        validateStartTime(newStartTime);
    }
    if (req.getEndTime() != null) {
        newEndTime = parseDateTime(req.getEndTime());
    }
    // 跨字段比较：用实际要写入的两个值来比较
    validateEndTime(newStartTime, newEndTime);
    
    // 5. 逐个字段更新（只更新非 null 字段）
    // ...
    
    eventMapper.updateById(event);
}
```

#### 10.2 抢票（purchase）业务逻辑

```java
@Transactional
public TicketResponse purchase(Long userId, PurchaseRequest req) {
    // 1. 查询活动是否存在
    Event event = eventMapper.selectById(req.getEventId());
    if (event == null) throw new BizException(4003, "活动不存在");
    
    // 2. 校验活动状态
    if ("offline".equals(event.getStatus()))
        throw new BizException(4100, "活动已下线，暂不可购票");
    if ("finished".equals(event.getStatus()))
        throw new BizException(4100, "活动已结束，暂不可购票");
    if ("draft".equals(event.getStatus()))
        throw new BizException(4100, "活动未上线，暂不可购票");
    
    // 3. 重复购票检查（数据库 UNIQUE 约束兜底）
    Long count = ticketMapper.selectCount(
        new LambdaQueryWrapper<Ticket>()
            .eq(Ticket::getEventId, req.getEventId())
            .eq(Ticket::getUserId, userId));
    if (count > 0) throw new BizException(4004, "您已购买过该活动的门票，请勿重复购买");
    
    // 4. 🔒 防超卖原子操作
    int affected = eventMapper.updateSoldTickets(req.getEventId()); // WHERE id=? AND sold_tickets < total_tickets
    if (affected == 0) throw new BizException(4100, "票已售罄");
    
    // 5. 生成 ticketNo
    String ticketNo = req.getEventId() + "_" + userId + "_" + (System.currentTimeMillis() / 1000);
    
    // 6. 插入 ticket 记录
    Ticket ticket = new Ticket();
    ticket.setEventId(req.getEventId());
    ticket.setUserId(userId);
    ticket.setTicketNo(ticketNo);
    ticket.setStatus("pending");
    ticketMapper.insert(ticket);
    
    // 7. 构建响应
    TicketResponse resp = new TicketResponse();
    resp.setTicketId(ticket.getId());
    resp.setTicketNo(ticketNo);
    resp.setEventTitle(event.getTitle());
    resp.setStatus("pending");
    return resp;
}
```

**关键点**：
- `eventMapper.updateSoldTickets()` 对应 XML：`UPDATE event SET sold_tickets = sold_tickets + 1 WHERE id = #{eventId} AND sold_tickets < total_tickets`
- 必须用 `@Transactional` 保证原子性
- 重复购票检查 + 防超卖 + 插入 ticket 在同一个事务中

#### 10.3 签到（checkin）业务逻辑

**是最复杂的方法**，严格按接口文档的流程伪代码翻译：

```java
@Transactional
public TicketResponse checkin(Long userId, CheckinRequest req) {
    String code = req.getCode();
    Long parsedEventId = null;
    String ticketNo = null;
    Long timestamp = null;
    
    // —— Step 1: 解析 code ——
    // 格式A（完整格式）：ticket_{eventId}_{ticketNo}_{timestamp}
    Pattern fullPattern = Pattern.compile("^ticket_(\\d+)_(.+)_(\\d{10,})$");
    Matcher m1 = fullPattern.matcher(code);
    if (m1.matches()) {
        parsedEventId = Long.parseLong(m1.group(1));
        ticketNo = m1.group(2);
        timestamp = Long.parseLong(m1.group(3));
        
        // —— Step 2: 校验时间戳（60秒内）——
        long now = System.currentTimeMillis() / 1000;
        if (now - timestamp > 60) {
            throw new BizException(4102, "二维码已过期，请刷新");
        }
    } else {
        // 格式B（手动输入）：ticket_{ticketNo}
        // ticketNo 格式为 {eventId}_{userId}_{timestamp}，如 "1_15_1718888888"
        Pattern simplePattern = Pattern.compile("^ticket_(\\d+_\\d+_\\d{10,})$");
        Matcher m2 = simplePattern.matcher(code);
        if (m2.matches()) {
            ticketNo = m2.group(1);
            // 手动输入跳过时间戳校验和 eventId 校验
        } else {
            throw new BizException(4101, "无效的签到凭证，格式不合法");
        }
    }
    
    // —— Step 3: 查询 ticket ——
    Ticket ticket = ticketMapper.selectOne(
        new LambdaQueryWrapper<Ticket>().eq(Ticket::getTicketNo, ticketNo));
    if (ticket == null) throw new BizException(4103, "票务不存在");
    
    // —— Step 3a: 校验 eventId 匹配（仅完整格式）——
    if (parsedEventId != null && !parsedEventId.equals(ticket.getEventId())) {
        throw new BizException(4101, "无效的签到凭证，票务与活动不匹配");
    }
    
    // —— Step 3b: 校验签到者是否为该活动的举办方 ——
    Event event = eventMapper.selectById(ticket.getEventId());
    if (event == null) throw new BizException(4003, "关联活动不存在");
    if (!event.getOrganizerId().equals(userId)) {
        throw new BizException(4002, "权限不足，您不是该活动的举办方");
    }
    
    // —— Step 3c: 校验活动是否已结束 ——
    if ("finished".equals(event.getStatus())) {
        throw new BizException(4107, "活动已结束，无法签到");
    }
    
    // —— Step 4: 检查 ticket 状态 ——
    String ticketStatus = ticket.getStatus();
    if ("checked".equals(ticketStatus)) throw new BizException(4104, "请勿重复签到");
    if ("invalid".equals(ticketStatus)) throw new BizException(4105, "票务已失效");
    if ("refunded".equals(ticketStatus)) throw new BizException(4106, "票务已退票");
    // 只有 pending 才继续
    
    // —— Step 5: 原子更新签到 ——
    int affected = ticketMapper.updateCheckin(ticket.getId()); // UPDATE ticket SET status='checked', checked_at=NOW() WHERE id=? AND status='pending'
    if (affected == 0) throw new BizException(4104, "请勿重复签到");
    
    // 构建响应
    TicketResponse resp = new TicketResponse();
    resp.setTicketNo(ticketNo);
    resp.setEventTitle(event.getTitle());
    resp.setCheckedAt(LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")));
    return resp;
}
```

**手动输入格式正则说明**：原计划使用 `^ticket_(.+)$`（过于宽松），现收紧为 `^ticket_(\d+_\d+_\d{10,})$`，要求：
- 第一部分：数字（eventId）
- 第二部分：数字（userId）

## 风险与注意事项

1. **事务一致性**：抢票（purchase）和删除（deleteEvent）必须加 `@Transactional`，且注意 MySQL 引擎为 InnoDB
2. **签到 code 正则的边界**：
   - 完整格式：`^ticket_(\\d+)_(.+)_(\\d{10,})$` — 用 `(.+)` 匹配 ticketNo 确保灵活
   - 手动输入：`^ticket_(\\d+_\\d+_\\d{10,})$` — 需按 ticketNo 实际格式（eventId_userId_timestamp）约束
3. **时间精度**：接口文档要求秒级时间戳，`System.currentTimeMillis() / 1000` 正确
4. **防超卖原子性原理**：`UPDATE ... WHERE sold_tickets < total_tickets` 是 MySQL 行级锁，无需额外悲观锁。前提条件是 where 条件命中索引（`id = ?` 命中主键索引）
5. **分页参数截断**：`size` 超过 100 时自动截断为 100，在 Controller 中处理
6. **UserContext 清空**：拦截器中 `afterCompletion` 需调用 `UserContext.clear()` 防止内存泄漏（基础设施已完成）
7. **`PageResponse<T>` 共享约定**：由另一成员维护，本模块只引用不创建。确认为 `com.easysign.dto.response.PageResponse` 包路径，包含 records/total/page/size/pages 五个字段
